# Debugger protocol + NSH debugger GUI for glscript

## Context

glscript has a complete bytecode VM (single `switch` loop in `Runtime::execute()`, `runtime.cpp:722`) but no way to observe a running script. The goal: a wire-level debugging protocol spoken over TCP by the VM, plus a debugger GUI built with NSH (nsh.dev, Longbridge's Rust-native UI framework — GTK4 backend, TSX components, virtualized lists) featuring source + bytecode panels, breakpoints, stepping, stack/locals, and expression evaluation. `glc` gains a run mode (`-r`) as part of this — it was already the remaining Stage 6 item.

Key facts from exploration (all verified):
- `FunctionBytecode::spans` is **one `SourceSpan` per code word** (`compiler.cpp:76-84`) — source mapping already exists; no compiler threading needed.
- `FunctionBytecode` has **no slot→name table**; `lower.cpp:40 declare()` is the single chokepoint where names are allocated then discarded.
- No disassembler exists; instruction boundaries are deterministic via `operand_count(op)`.
- Runtime is synchronous, single-threaded, **not thread-safe** → debug server must be cooperative: a hook invoked inside the dispatch loop that pumps the socket, blocking-pumping while paused.
- NSH TSX apps have a native `net` module (`connect({host,port})` with read/write), capability-gated via `nsh.json`; virtualized `List`, monospace `Text` rows with `onPress`, `<Input>` cover the GUI needs. GTK4 headers + clang already present on this machine. NSH is pre-1.0 (v0.5.0, 2026-11-11) — pin `NSH_VERSION` at install.

## Plan

### 1. Plan doc (committed first, per project pattern)
`docs/debugger-plan.md` — architecture, protocol spec (message tables), status header. Updated at completion like prior plan docs.

### 2. Runtime debug hooks (core, dependency-free)
- `include/glscript/debug.hpp`: `DebugHook` interface — `on_instruction(Runtime&, frame_index, ip, span)` called at the top of the dispatch loop (`runtime.cpp:734`, after span fetch, before switch, guarded by null check). Returning does nothing; the hook itself decides to block (pump protocol while paused).
- `runtime.hpp`: `set_debug_hook(DebugHook*)` + a small public "debugger access" section: const accessors for `frames_` (function index, ip, base, resumed_slice flag), `stack_` value reads, `handlers_` size, `result_`, `failed_`. No mutation exposed.
- Slot names: add `std::vector<std::string> local_names` to `hir::Function` (fill in `declare()`, `lower.cpp:40`) and to `FunctionBytecode` (`bytecode.hpp:77`); the emitter copies it. Hidden slots (`$matchN`/`$patN`/`$letN`, receiver, continuation) keep `$`-prefixed names — debugger filters them for display.

### 3. Disassembler
`include/glscript/disasm.hpp` + `src/disasm.cpp`: render a `FunctionBytecode` to structured lines `{ip, op name, decoded operands (constants/tables/jump targets), source line}`. Shared by `glc --dump-bytecode` and the protocol's `disassemble` command.

### 4. Debug protocol + TCP server (`src/debug_server.cpp`)
- NDJSON (newline-delimited JSON) over TCP; JSON via nlohmann single-header fetched with `file(DOWNLOAD)` (EnTT precedent in CMakeLists).
- `DebugServer` implements `DebugHook`: nonblocking `accept`/`recv` while running; `select()`-blocking pump while paused. One client at a time; binds at startup, **waits for first connection before running** (interactive-debugger semantics), then emits `stopped {reason: "entry"}`.
- Requests: `set_breakpoints {file, lines[]}`, `continue`, `pause`, `step_in`, `step_over` (line-based: stop when frame depth ≤ saved depth and line changes), `stack_trace`, `scopes {frame_index}` (locals + handler info), `variables {ref}` (lazy tree: object fields via `TypeSymbol::fields`, array elements, enum payload — refs valid only while paused), `evaluate {frame_index, expression}`, `disassemble {function_index}`, `source {file}`.
- Events: `stopped {reason, ip, function, line}`, `output {text}` (print sink taps), `exited {failed, result}`.
- Breakpoints: map file→line set; hook checks `span` line each instruction. Values stringified via `Runtime::stringify`; objects get `"<Type.Name>"` + expandable fields.
- **Evaluate**: `src/dbg_eval.cpp` — standalone recursive evaluator over the snippet's parsed AST (reuse lexer/parser): literals, identifiers (paused frame's named locals; array index; field read), arithmetic/comparison/`!`/`-`/ternary. **No calls** — the interpreter is non-reentrant; unsupported calls produce a clear diagnostic. Documented in plan doc.

### 5. `glc` run mode + demo script
- `tools/glc.cpp`: `-r script.gl` (compile + `Runtime::run("module", "main")`), `--debug[=port]` (default 9000) installs the `DebugServer`; `--dump-bytecode`. glc links core + `register_std` + stdout print sink only.
- `examples/debug/target.gl`: demo script exercising arrays, match, effects/handle, loops — the thing you debug in the GUI.

### 6. Tests (`tests/debugger_test.cpp`, new ctest suite)
In-process end-to-end over real sockets: run script under `DebugServer` on a background thread, drive the protocol from the test thread (raw POSIX client) — assert entry stop, breakpoint hit at the right line/stack, stepping semantics, locals contents, evaluate results, disassemble output.

### 7. NSH debugger GUI (`tools/debugger/`)
- Install `nsh` CLI (`curl -fsSL https://nsh.dev/install.sh | sh`, pinned `NSH_VERSION=v0.5.0`); `nsh init --template ts`; `nsh.json` grants `"network": {"sockets": ["127.0.0.1:9000"]}`.
- Layout: toolbar (host:port connect, continue/pause/step-in/step-over, status) · left: source panel (virtualized rows, breakpoint gutter via row `onPress`, current-line highlight, `scrollToIndex`) · right: bytecode panel (function selector + instruction rows, current-ip highlight) · bottom: stack trace, variables tree, evaluate input + result line.
- Signals for state; one protocol module framing NDJSON over `net.connect`; reconnect handling.

### 8. Wrap-up
README debugger section, `docs/status.md` milestone note, memory update.

## Verification
1. `cmake --build build && ctest` — all existing suites + new `debugger_test` green.
2. `glc --dump-bytecode examples/debug/target.gl` renders correct disassembly.
3. Manual end-to-end: `glc -r --debug examples/debug/target.gl` in one terminal, `nsh run tools/debugger` in another — connect, set breakpoints in the source panel, step, inspect locals, evaluate expressions (e.g. `total * 2`), watch bytecode ip track execution.
4. `nsh check` in `tools/debugger` for TS type cleanliness.

## Risks
- NSH pre-1.0 API churn → pin version, keep GUI code in one place; GTK4 runtime libs already present.
- `resumed_slice` frames from continuation splices are shown in the backtrace with a "(resumed)" marker; suspended continuations themselves are out of scope for v1.
