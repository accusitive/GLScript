# Runtime milestone: script → bytecode → interpreter with multi-shot handlers + GC

## Context

The typechecker milestone is committed (`99cfc56`). The README names the next milestone: executing scripts with **multi-shot resumable effect handlers** plus a **host-call bridge**, ending with `entt_demo` actually running `update()`. Two constraints from exploration:

- `CheckerImpl` (ASTs, symbol tables, per-node resolutions) is anonymous-namespace and destroyed in `check_source` (src/checker.cpp:2729) — nothing survives for a compiler to consume.
- `HostRegistry` schemas are signature-only; no callables exist anywhere (include/glscript/host.hpp).

Per user approval: free to use `std::variant` and restructure as needed; **GC story required**.

## Core architecture

- **Stack-machine interpreter** where all machine state (value stack, call frames, handler frames) lives in interpreter-owned vectors. Capturing a delimited continuation = copying frames/value-stack slice above the handler delimiter; multi-shot `resume` = replaying a copy of that snapshot. Handler stays installed while the continuation runs, so ops raised inside a resumed continuation are re-handled.
- **GC: non-moving mark-sweep tracing heap** owned by the interpreter. All heap values (strings, enum instances, script objects, closures, continuations) allocate from a flat arena the `Heap` owns. Roots = interpreter state: value stack, frames/upvalues, globals, handler frames, and continuation snapshots (which is what makes multi-shot resume safe — captured continuations keep arbitrary graphs alive). Triggered on allocation threshold + explicit `gc_collect()` for engine frame boundaries. Host/foreign pointers are *not* GC-managed (engine owns them). Non-moving keeps `void*` handles and object identity stable; mark-sweep handles cycles.

- `include/glscript/symbols.hpp` (new): move `FieldSymbol`, `EnumVariantSymbol`, `OperatorInfo`, `FunctionSymbol`, `TypeSymbol`, `Symbol`, `Scope`, `ModuleInfo` out of checker.cpp's anonymous namespace; add `Program{modules, sources, scopes, builtin_functions, types_by_qname, find_type()}`. Add `FieldSymbol::index` (slot order) and `Symbol::field` (so bare field names inside methods bind as field accesses).
- `include/glscript/ast.hpp`: add `Binding binding` to `Expr` (checker decorates; compiler consumes).
- `src/checker.cpp`: include symbols.hpp; record bindings in `check_identifier`, `resolve_callee`, `check_member`, `check_assignment_target`, `check_binary`/`check_unary` (custom ops → `Operator`; everything else stays intrinsic), `check_downcast`; extend `find_field` to output `FieldSymbol*`, `find_operator` to output `OperatorInfo*`; assign field indexes.
- `include/glscript/checker.hpp`: `Frontend::program()`; `Frontend::Impl` retains the last `std::unique_ptr<Program>`; `CheckerImpl::take_program()` moves all retained state out.

## Stage 2 — Value + GC heap (`include/glscript/value.hpp`, src/value.cpp)

`Value` as `std::variant`-based tagged struct: unit/bool/int64/double inline; heap kinds as `GcPtr` (raw pointer into Heap) for `StringObj`, `EnumObj` (variant id + payload), `ObjectInstance` (TypeSymbol*, field slots, optional host `void*` for engine-backed instances — unifies host handles and script objects), `Closure` (fn index + captures), `Continuation` (copied machine state). `Heap` owns `std::vector<std::unique_ptr<GcObject>>` with mark bits; `GcObject::trace()` walks payloads; `clone()` deep-copies continuations' frames while sharing objects.

## Stage 3 — Bytecode + compiler (`include/glscript/bytecode.hpp`, src/compiler.cpp)

`Chunk{code, constants, spans}`, `FunctionBytecode{name, param_count, local_count, chunk, captures}`, `CompiledProgram{functions}`. Ops: LoadConst/LoadLocal/StoreLocal/LoadCapture, intrinsic arithmetic/compare/logic + Concat (runtime-dispatched on int/float/string/dynamic), Jump/JumpIfFalse/JumpIfTrue/Loop, Call, CallHost, NewObject, GetField/StoreField, EnumCtor, GetMethod, Downcast, PushHandler/PopHandler/Raise/Resume, BuildString (template), Closure, Dup/Pop, Return. `Compiler(const Program&)` walks FunctionDecl bodies with a local-slot scope stack; handler case bodies compile as separate functions with an implicit continuation slot; per module an init function for top-level `HandlerDecl`s.

## Stage 4 — Interpreter (`include/glscript/runtime.hpp`, src/runtime.cpp)

`Runtime(const CompiledProgram&, const HostRegistry&, DiagnosticSink&)`, `Value run(module, function, args)`. State: value stack, `CallFrame{fn, ip, base}`, `HandlerFrame{(effect::op → handler fn), delimiter}`. Raise: scan handlers top-down; found → capture continuation (copy frames + stack slice + inner handler frames above delimiter), call handler fn with args + continuation; none → host thunk if present, else runtime error via DiagnosticSink (spans from chunk). Resume: clone snapshot, install, push resume value as raise result. `#[abort]`/failed downcast → fatal runtime error. Allocations go through Heap; collection at threshold.

## Stage 5 — Host-call bridge (host.hpp, host.cpp, checker plumbing)

`using HostCall = std::function<Value(std::vector<Value>& args)>` (receiver = args[0] for methods); `FunctionBuilder::call(...)` stores it on `FunctionSchema`; checker plumbs into `FunctionSymbol` during `resolve_host_signatures`. Interpreter calls it for host functions/methods and as the default for host effect ops with no installed handler.
